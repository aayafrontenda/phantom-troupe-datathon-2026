# Frontend + сдача — инструкция

**Кто:** MacBook Air M1.
**Отвечаешь за:** интерфейс (`backend/static/`) и `docs/` — пакет сдачи (раздел 8 ТЗ) и слайды.

> **Статус (17.10):** интерфейс сделан как single-page app без сборки — `backend/static/index.html`, `app.css`, `app.js`
> (дизайн из прототипа «CashGuard Prototype», подключён к реальному API). Node и React не нужны: бэкенд отдаёт статику
> как есть, на ROG ничего ставить не надо. Если захочется React — делай в `frontend/`, сборка в `frontend/dist`
> подхватится автоматически (см. `backend/app/main.py`), но текущий UI уже закрывает весь сценарий раздела 4 ТЗ.

## Что уже есть в интерфейсе

| Экран | Что делает |
| --- | --- |
| Review → New check | drag&drop / выбор `.mov`, прогресс загрузки, ошибки 400/413/429 |
| Processing | шаги `upload → queue → frames → detection → vlm → report` по SSE, место в очереди и ETA, превью видео |
| Result | вердикт дословно по ТЗ, плеер (загруженный файл или `/ui/api/jobs/{id}/video`), цепочка доказательств: кадры → что видно → норма с цитатой и ссылкой на adilet; «Подтвердить / Ложное» → feedback; кнопка Report (акт для печати), клип 10 с |
| Timeline | шкала с маркерами нарушений, AI-проверки (`meta.candidates`), дорожки `timeline` (люди, экран, телефон, еда, сумка), скраб, клавиши Space/←→/N/P/C/R |
| Side panel | список алармов с прогрессом проверки; AI trace — воронка и сцены (`meta.scenes`) |
| Live wall | камеры сервера (RTSP/файл) по WebSocket с рамками, камера ноутбука через `/ui/api/live`, добавление камеры (admin-ключ), панель алертов с Acknowledge / False и SSE |
| Rules | таблица типов из `/ui/api/rules` с цитатами и ссылками |

Все данные — из `docs/api_contract.md`. Admin-ключ для камер хранится в localStorage браузера (`cg_admin_key`).

## Питч (5 минут + 2 вопросы, только для финалистов)

1. Проблема: ручной просмотр видео кассы — долго (20 с).
2. Демо: загрузка видео → вердикт → карточка с кадром, таймкодом и нормой (90 с).
3. Live-режим вживую на камере ноутбука (40 с).
4. Как работает: детектор → кандидаты → локальная VLM → правила с нормами; полностью локально, лицензии Apache/MIT (60 с).
5. Качество на обучающих видео и устойчивость к новому ракурсу — цифры от ML (40 с).
6. Развитие: обратная связь проверяющих, RTSP к существующим камерам, новые правила добавляются в YAML (30 с).
