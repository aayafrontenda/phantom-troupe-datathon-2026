# Frontend + сдача - инструкция

**Кто:** MacBook Air M1.
**Отвечаешь за:** интерфейс (`frontend/`) и `docs/` - пакет сдачи (раздел 8 ТЗ) и слайды.

> **Статус (17.10):** интерфейс переписан на React + Vite + TypeScript в дизайне forte.kz (`frontend/`).
> Роли и два рабочих места: оператор (мониторинг камер + события, проверка видео) и супервайзер/админ (контроль решений).
> Бэкенд отдаёт собранный `frontend/dist`; `deploy/run_server.sh` и Docker собирают его сами.

## Как работать

```bash
cd frontend
npm ci
npm run dev        # http://127.0.0.1:5173, API проксируется на :8000 (бэкенд: ./deploy/run_server.sh)
npm run build      # frontend/dist - то, что отдаёт бэкенд
npm run typecheck
```

Структура:

```
src/main.tsx, App.tsx        провайдеры (i18n, UI, auth), роуты по ролям
src/api.ts                   fetch-обёртка (cookie-сессия, 401 → экран входа)
src/auth.tsx                 текущий пользователь, login/logout, can(role)
src/i18n/strings.ts          все строки интерфейса ru / kk / en (ключи должны совпадать во всех трёх - проверяется тестом)
src/i18n/index.tsx           t(), переводы типов нарушений и норм (backend/i18n-kb.json через /ui/api/i18n/kb)
src/styles/app.css           дизайн-система (токены, кнопки, карточки, тёмная тема)
src/components/              Header, Player (видео + маркеры; SequencePlayer для кадров с камеры), finding (кадры, описание,
                             редактор формулировки, норма, решение, проверка супервайзера), events (общий SSE-поток находок), uploads
src/pages/                   Login, Live (оператор), Checks, Check, Finding, Review (супервайзер), Rules, Admin
```

Экраны:

| Экран | Кому | Что делает |
| --- | --- | --- |
| `/live` Мониторинг | все | камеры в реальном времени (WebSocket, рамки детекций), справа лента событий со всех камер и загрузок; клик → `/findings/:id` |
| `/checks`, `/checks/:id` Проверка видео | все | загрузка `.mov`, прогресс по SSE, результат: плеер с маркерами, карточки находок (кадры, что видно, норма), уточнение формулировки, «Да / Нет», отчёт |
| `/findings/:id` Находка | все | один момент: клип/кадры с камеры или видео загрузки, описание ИИ и формулировка оператора, решение, проверка супервайзера, история, соседние находки |
| `/review` Контроль | supervisor, admin | все решения операторов: фильтры «отклонил оператор», «проверить», «проверено», «супервайзер не согласен», источник, тип, оператор, период; экспорт CSV |
| `/quality` Качество ИИ | supervisor, admin | точность ИИ по проверенным находкам, подтверждаемость по типам с адаптивными порогами, ложные срабатывания по неделям, таблица операторов (подсветка проблемных), «Выгрузить датасет» |
| `/admin` Администрирование | admin | пользователи и роли (камеры по операторам), камеры, состояние сервиса |
| `/rules` Правила | все | типы нарушений и нормы с цитатами |

Правила кода: все строки через `t()` (новый ключ - сразу в ru, kk и en), классы и токены из `app.css`,
никаких внешних UI-библиотек, логика с API - в `docs/api_contract.md`.

## Питч (5 минут + 2 вопросы, только для финалистов)

1. Проблема: ручной просмотр видео кассы - долго (20 с).
2. Демо оператора: событие с камеры → момент, кадры, норма → уточнил формулировку → решение (60 с).
3. Демо супервайзера: контроль - где ИИ и оператор разошлись, проверка, отчёт (40 с).
4. Загрузка видео → вердикт → отчёт для акта (40 с).
5. Как работает: детектор → кандидаты → локальная VLM → правила с нормами; полностью локально, лицензии Apache/MIT (60 с).
6. Качество на обучающих видео и устойчивость к новому ракурсу - цифры от ML (40 с).
