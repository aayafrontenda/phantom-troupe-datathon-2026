# PhantomGuard - выявление нарушений кассовой дисциплины по видео

Datathon 26, кейс ForteBank. Локальный AI-сервис: загружаете видео с камеры над кассой - получаете вердикт,
нарушения с таймкодом, кадрами-доказательствами, описанием и ссылкой на норму РК.
Все модели работают внутри сервиса, облачные AI-API не используются.

## Типы нарушений

| Код | Нарушение | Что видит сервис | Норма |
| --- | --- | --- | --- |
| T01 | Компьютер не заблокирован при уходе | кассир ушёл, на экране окно программы, а не экран блокировки | НБРК № 34 п. 7, п. 4 пп. 1; АРРФР № 53 п. 71 пп. 9 (косвенная) |
| T02 | Наличные или ценности без присмотра | кассир ушёл, на столе деньги, сумка или другие предметы | Правила № 231 п. 20, 22 |
| T03 | Сейф открыт без присмотра | кассир отошёл от открытого сейфа | Правила № 231 п. 20, 80 |
| T04 | Дверь кассы не закрыта | участок двери не вернулся к закрытому виду после входа или выхода | Правила № 14 п. 8, 16 пп. 1 |
| T05 | Посторонний в кассе | второй человек на стороне кассира, вплотную к нему, не меньше 3 с | Правила № 14 п. 8; Правила № 231 п. 75 |
| T07 | Деньги прошлого клиента при входе следующего | клиент ушёл, наличные остались на столе, подходит следующий клиент | Правила № 231 п. 20 |
| T09 | Клиент ушёл до завершения операции | клиент уходит, когда кассир встала работать с его деньгами | Правила № 231 п. 20 |
| T11 | Сумка инкассатора без оформления | второй человек принёс сумку, через 2–15 с ушёл, сумка осталась | Правила № 231 п. 24 |
| T12 | Ценности в сейф без пересчёта | инкассаторские сумки, деньги на столе меньше 30 с, затем открыт сейф | Правила № 231 п. 42, 74 (косвенная) |
| T13 | Личные вещи на рабочем месте | сумка, рюкзак или одежда кассира на столе | Правила № 231 п. 12 |
| T14 | Еда или напитки при работе с наличными | кассир пьёт или ест, детектор видит стакан, бутылку или еду | Правила № 231 п. 12 (косвенная) |
| T15 | Смартфон в кассе | телефон в руке кассира, ближе к кассиру, чем к клиенту | Правила № 231 п. 12 |
| T16 | Кассир ушёл во время обслуживания | место кассира пусто, клиент у стола | Правила № 231 п. 22 |

Полные названия документов, пункты и дословные цитаты - [docs/norms.md](docs/norms.md). Где прямой нормы нет, сервис
так и пишет («норма косвенная») и объясняет, почему.

## Быстрый старт

**Docker (любая машина):** `./deploy/docker.sh` на Mac/Linux или `deploy\docker.ps1 -Tunnel` на Windows с GPU - см. `deploy/DOCKER.md`.

**Mac / без GPU (mock-анализатор, тот же формат ответа):**
```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
pytest -q
./deploy/run_server.sh          # http://127.0.0.1:8000 (соберёт интерфейс из frontend/, нужен Node 20+)
```
Вход: пользователи из `SEED_USERS` в `.env` (admin / operator / supervisor, пароли там же).

**ROG / Windows с моделью:**
```powershell
python -m venv .venv; .\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
pip install torch torchvision --index-url https://download.pytorch.org/whl/cu128
pip install -r ml\requirements-ml.txt
ollama pull qwen3.5:4b
copy .env.example .env           # ANALYZER=ml
powershell -ExecutionPolicy Bypass -File deploy\run_server.ps1
```

Датасет кейса кладите в `data/open/` (папка в `.gitignore` - видео кейса публиковать нельзя).

## Как пользоваться

Интерфейс - http://127.0.0.1:8000, вход под одной из ролей из `SEED_USERS` (логины `operator`, `supervisor`, `admin`).

1. **Проверка видео** (стартовая страница): перетащите `.mov` - виден прогресс по стадиям, затем вердикт и карточки находок:
   кадры-доказательства, таймкод в плеере, описание ИИ и норма с цитатой. Оператор уточняет формулировку и решает «нарушение / нет».
2. **Контроль** (супервайзер): все решения операторов рядом с описанием ИИ; фильтр «ИИ увидел нарушение, оператор отклонил»;
   отметка «проверено: согласен / не согласен»; выгрузка CSV. **Качество ИИ**: точность по типам, адаптивные пороги, датасет для дообучения.
3. **Мониторинг**: камеры в реальном времени (RTSP, веб-камера или файл), тревоги становятся находками с фрагментом видео.
4. **Отчёт**: печатная форма проверки (`report.html`, ru/kk/en) для акта.

Уведомления в Telegram (меню профиля → Telegram). Три языка: русский, казахский, английский. Swagger - `/docs`.

## API (раздел 10 ТЗ)

```bash
curl -X POST http://127.0.0.1:8000/api/v1/analyze -H "X-API-Key: <ключ>" -F "file=@video.mov"
curl http://127.0.0.1:8000/api/v1/jobs/<job_id> -H "X-API-Key: <ключ>"
```

Ключ - `API_KEY` в `.env` или сгенерированный в `storage/api_key.txt`. Подробно - `docs/api_contract.md`, Swagger - `/docs`.

Сервис отвечает **всегда до 5 минут**: анализ идёт в отдельном процессе под сторожевым таймером, при зависании или падении
возвращается частичный результат, а не `failed`. Задачи жюри идут в очереди первыми; когда видео приходят пачкой, время
делится между ними (`MIN_JOB_BUDGET_SEC` - минимум на одно видео). Повторная загрузка того же файла отдаёт результат мгновенно.
Файл принимается по содержимому, а не по расширению. Устройство сервиса - `docs/backend.md`.

## Архитектура

Сервис: FastAPI → SQLite → пул воркеров-процессов (приоритет жюри, сторожевой таймер, ретраи) → находки
(описание ИИ → правка и решение оператора → проверка супервайзера) → алерты (web/Telegram/webhook/e-mail, эскалация)
→ отчёты. Live: RTSP/файл-камеры с фрагментом вокруг каждой тревоги, браузер по WebSocket. Интерфейс: React (`frontend/`).
Подробно - `docs/backend.md`, `docs/api_contract.md`.

Пайплайн анализа:

```
видео .mov ─► кадры 2 fps ─► RT-DETR (люди, ноутбук, сумки, телефон, напитки)
                                  │
       ┌──────────────────────────┼──────────────────────────┐
       ▼                          ▼                          ▼
 рабочее место:             рамки детектора:           дверь кассы:
 увеличенный фрагмент       второй человек рядом       участок двери
 вокруг ноутбука            с кассиром, сумка          против эталона
       │ (≤ 26 вызовов)     инкассатора                (без VLM)
       ▼                          │                          │
 Qwen3.5-4B (локально, Ollama)    ▼                          ▼
 отвечает на вопросы о фактах: T05 T11                      T04
 кассир на месте? экран?
 деньги? сейф? пьёт? телефон?
       │
       ▼
 правила по дорожке состояний → T01 T02 T03 T07 T09 T12 T13 T14 T15 T16
       │
       ▼
 слияние ─► rules_kb.yaml (тип, описание, норма) ─► JSON по ТЗ
```

VLM не решает «есть ли нарушение» - она отвечает на простые вопросы о том, что видно, а нарушение выводят
правила. Так на обучающих видео ложные срабатывания упали с 19 из 20 до нуля (подробно - `docs/ml.md`).

Для проверяющих: модель, распознаваемые типы, метрики, ограничения и известные ошибки - [`docs/ml.md`](docs/ml.md);
нормативные источники и сопоставление «нарушение → норма → цитата» - [`docs/norms.md`](docs/norms.md);
результат по каждому обучающему видео - [`docs/eval_report.csv`](docs/eval_report.csv).

Модели и лицензии: RT-DETR r18 (Apache-2.0), Qwen3.5-4B (Apache-2.0), Ollama (MIT), OpenCV (Apache-2.0), FastAPI (MIT).
